# 健康管理系統・第二、三批規格

接續第一版（登記頁、教師看板已完成）。本文件涵蓋：

- **第二批**：健康分析（規則引擎）
- **第三批**：SMART 目標設定 + 四週行動打卡

資料表沿用 `hc_` 前綴，RLS 比照既有兩張表。

# 第二批・健康分析（規則引擎）

## A. 設計原則

**這一批完全不呼叫 AI。** 所有判讀與建議都是規則對應，理由：零成本、秒回、學生健康資料不外流、輸出可預期可審閱。AI 留到之後有需要再說。

輸出對象是學生自己，所以：

- 用字中性，不出現「異常」「高血壓」「肥胖」
- **不顯示任何目標體重、該減幾公斤、熱量赤字**
- 不排名、不與同學比較
- 心理檢測高風險時，走固定關懷文案，**不進入分析引擎、不給生活習慣建議**

## B. 資料來源

讀 `hc_health_measurement`（期初那筆）+ `hc_health_selfcheck`，不新增資料表。分析結果現算不落盤——資料改了分析就跟著改，維持單一真相來源。

## C. 分析流程

```
1. 檢查心理紅旗
   depression_critical 或 needs_followup = true
   → 只顯示固定關懷文案，流程結束，不往下跑
2. 各項目判燈號（沿用 rules.ts 既有門檻）
3. 依三級優先序排序，取前 1-2 項為「優先改善」
4. 從建議庫取出對應建議
5. 組成分析頁
```

## D. 優先序（照原 GEM 架構）

| 級別 | 項目 | 說明 |
|---|---|---|
| 第一級・身體訊號 | 血壓、BMI 明顯偏離 | 最優先，但用中性語言，導向「再測一次 + 找老師談」 |
| 第二級・學習效能 | 睡眠不足、壓力偏高、心情低落 | 對課業表現最直接，學生最有感 |
| 第三級・長期健康 | 飲食不均、活動量少、螢幕時間長 | 影響慢但可塑性最高 |

同級內有多項時，取偏離程度較大者。**最多顯示 2 項**——原 GEM 的設計就是抓 1-2 個優先習慣，給太多等於沒給。

## E. 分析頁版面

```
① 這學期的起點      三色燈號總覽（BMI / 血壓 / 腰臀比 / 85210 達成幾項）
② 先從這裡開始      1-2 個優先改善項目，每項含：
                      · 現況（中性描述）
                      · 為什麼值得改（對生活、學習的影響）
                      · 難度（★1-5）與所需時間
                      · 立即可行的第一小步
③ 三個改善建議      從建議庫取，附科學依據一句話
④ 兩到三個運動建議  含能量消耗、頻率、漸進計劃
⑤ 下一步            導向 SMART 目標設定頁
```

## F. 建議庫（`suggestions.ts`）

每筆結構：

```ts
{
  id: 'sleep-01',
  domain: 'sleep',          // sleep | diet | activity | stress | hydration | screen
  trigger: ['sleep_under_6', 'sleep_6_7'],
  title: '倒推計劃法',
  why: '固定起床時間比固定就寢時間更容易建立生理時鐘。',
  how: '先決定起床時間，往前推 8 小時就是該上床的時間，設成手機鬧鐘提醒。',
  difficulty: 2,            // ★1-5
  timeframe: '2 週',
  firstStep: '今晚設一個「準備睡覺」的鬧鐘。'
}
```

### 起始建議庫內容（取自原 GEM，可再擴充）

**睡眠**
- 2-2-2 法則：睡前 2 小時不重食、不劇烈運動、不藍光
- 倒推計劃法：先定起床時間再往前推
- 15 分鐘原則：躺 15 分鐘睡不著就起來做低刺激的事
- 手機放書桌不帶進房間
- 4-7-8 呼吸法、漸進式肌肉放鬆

**飲食**
- 點餐技巧：買便當主動要求多菜少飯（不加錢）
- 用餐順序：先湯、再菜、後肉、最後飯
- 便利商店選擇：高纖飯糰、無糖茶、低鈉沙拉、無調味蛋
- 速食選烤不選炸、飲料無糖少冰
- 80/20 法則：八成時間顧好，兩成放鬆，不要全有全無

**活動量**
- 爬樓梯取代電梯（免費）
- 晚自習後教室做 5 分鐘伸展
- 午休到操場走走
- 通勤時間做肌力操、等公車時深呼吸
- 在家做徒手訓練（不需器材）

**壓力**
- 番茄鐘學習法
- 優先級排序、暫時性筆記
- 善用早晨時段而非熬夜
- 考試週降低標準但不中斷

**飲水**
- 上學前先喝 200ml
- 帶固定容量水壺，用「今天喝完幾瓶」計數

## G. 百分位數（已定案）

**學生端不做百分位、不做任何同儕比較。** 學生只看得到自己的數值與參考範圍。

**教師端可以看。** 在教師端提供：

- 全校同年級各項目的分布（BMI、體脂率、腰臀比、血壓）
- 單一學生在分布中的位置（百分位）
- 班級間比較（用於課程設計）

資料用本學期 177 筆現算。教師端呈現百分位時要標註樣本數，單學期樣本小、數字僅供課程參考，不是常模。

# 第三批・SMART 目標與四週打卡

## A. 資料表

```sql
create table hc_health_goal (
  id            uuid primary key default gen_random_uuid(),
  student_email text not null,
  semester      text not null,

  domain        text not null,   -- sleep | diet | activity | stress | hydration | screen
  s_action      text not null,   -- 具體行動
  m_method      text not null,   -- 測量方法
  baseline      text,            -- 現況基準：學生自述目前實際狀況
  confidence    smallint,        -- 0-10，學生自評做得到的把握
  a_reason      text,            -- 為什麼做得到
  r_relation    text,            -- 與健康/課業的關聯
  t_start       date not null,
  t_end         date not null,
  target_per_week smallint not null default 3
    check (target_per_week between 3 and 7),   -- 一週七天內至少三天達標

  status        text not null default 'active', -- active | done | dropped
  created_at    timestamptz default now(),
  updated_at    timestamptz default now()
);

create table hc_health_checkin (
  id            uuid primary key default gen_random_uuid(),
  goal_id       uuid not null references hc_health_goal(id) on delete cascade,
  student_email text not null,
  semester      text not null,
  check_date    date not null,
  done          boolean not null default true,
  note          text,            -- 一行備註，選填
  created_at    timestamptz default now(),
  unique (goal_id, check_date)
);
```

RLS 比照既有表：學生只能讀寫自己的、教師唯讀自己班、anon 無權。`student_email` 寫入時同樣過 `hc_is_known_student_email()`。

照片欄位**先不要加**，第四批做 R2 時再上。

## B. 目標設定精靈

六步，一步一頁，手機一次看一題：

| 步驟 | 問學生 | 輔助 |
|---|---|---|
| 1. 選領域 | 你想先改善哪一塊？ | 只顯示第二批分析出來的 1-2 個優先項目 + 「其他」 |
| 2. 現況基準 | **你現在實際上是怎樣？** | 一句話或數字。例：「平常一天睡 4 小時」 |
| 3. S 具體行動 | 你要做什麼？ | 提供 4-5 個範例可直接選，也能自己打 |
| 4. 可行性自評 | **你覺得自己做得到的把握有幾分？（0-10）** | 拉桿。低於 7 分觸發調整建議，見下方 |
| 5. M + A + R | 怎麼知道你做到了？為什麼你做得到？這對你有什麼幫助？ | 各一句，M 預設「每天在這裡打卡」 |
| 6. T 時間 | 每週要做到幾天？ | **最少 3 天、最多 7 天，預設 3 天**，四週。起訖日期自動帶 |

**一次最多 3 個目標。** 設第四個時提示「先把這三個做穩再加」。

## B-1. 可行性檢查（本批的核心要求）

蕾蕾的明確要求：**小目標要以學生自己評量做得到為主。** 系統要主動攔下「現況與目標落差過大」的設定。

### 兩道檢查

**第一道：落差檢查（第 2 步 vs 第 3 步）**

在可量化的領域（睡眠時數、飲水量、運動次數、螢幕時間），比對現況與目標：

| 落差 | 系統反應 |
|---|---|
| 小（≤ 25%） | 直接通過 |
| 中（25-50%） | 溫和提示：「這是一步跨得有點大的目標，要不要先試試中間值？」並給出建議數字 |
| 大（> 50%） | 強提示，並預設幫他改成中間值（仍可改回去） |

範例：現況一天睡 4 小時，目標 8 小時 → 落差 100% → 提示「從 4 小時直接跳到 8 小時很難維持。先設 5.5 小時，兩週穩了再往上加？」

**第二道：信心分數（第 4 步）**

問「你覺得自己做得到的把握有幾分？0 到 10」。

| 分數 | 系統反應 |
|---|---|
| 7-10 | 通過，「很好，這個目標你有把握」 |
| 4-6 | 「把握不夠高的目標，通常撐不過第二週。要不要把目標調小一點，讓把握變成 8 分？」提供調整選項 |
| 0-3 | 同上，並預設縮小目標（降低天數或降低強度） |

### 重要：提示，不阻擋

兩道檢查都只提示，**學生堅持原目標仍可送出**。自主性是這個單元的教學目標之一，系統不該替他決定。但提示要說清楚理由，讓他知道為什麼建議改。

### 落差檢查的量化對照

| 領域 | 現況欄位 | 中間值算法 |
|---|---|---|
| 睡眠 | 目前平均睡幾小時 | 現況 + (目標 − 現況) × 0.4，取 0.5 小時為單位 |
| 飲水 | 目前一天喝幾 ml | 同上，取 100ml 為單位 |
| 運動 | 目前一週動幾次 | 同上，取 1 次為單位 |
| 螢幕 | 目前睡前滑多久 | 同上，取 15 分鐘為單位 |

非量化領域（飲食習慣、壓力）只跑信心分數那道。

### 範例庫（行為型，不用身體數字）

| 領域 | 範例 |
|---|---|
| 睡眠 | 晚上 11 點後把手機放書桌不帶進房間 / 睡前 30 分鐘不滑手機 |
| 飲食 | 每次買便當都要求多菜少飯 / 便當先吃完菜再吃肉 / 每天吃早餐 |
| 活動 | 每天晚自習後做 5 分鐘伸展 / 爬樓梯不搭電梯 / 每週打球 3 次 |
| 飲水 | 每天上學前喝 200ml 白開水 / 帶水壺喝完兩瓶 |
| 螢幕 | 寫作業時手機放抽屜 / 睡前不看短影片 |

**禁止出現**：減重幾公斤、體脂降到多少、每天幾大卡。

## C. 四週打卡頁

```
今天        [ 今天做到了 ] ← 一顆大按鈕，點下去就完成
            （可展開加一行備註）

本週        ○ ● ● ○ ● ─ ─     3 / 5 天
四週總覽    月曆格狀，做到的填色
            連續天數、四週累計
```

### 互動原則

- 打卡按鈕**一次點擊完成**，不要跳確認框
- 可以補登前幾天（學生會忘記），但不能補未來
- **斷掉不責備**。不要「你中斷了連續 5 天紀錄！」這種文案，改成「今天是新的一天，繼續」
- 完成率低時不出現任何負面評價，只呈現事實與鼓勵

## D. 教師端

在既有進度看板加一個分頁：

| 欄位 | 內容 |
|---|---|
| 目標設定狀態 | 誰設了、誰還沒設 |
| 四週打卡熱區 | 每生一列，四週 28 格，一眼看出誰在做、誰停了 |
| 本週完成率 | 班級整體百分比 |

**不做個人排行榜、不做班級競賽。** 同儕壓力加上身體意象的組合，對這個年紀風險太高。班級整體完成率可以做，用於課堂回饋。

## E. 時程對應

| 週次 | 學生做什麼 |
|---|---|
| W1 | 測量、登記數值、做自我檢測 |
| W2 | 看分析頁、設定 SMART 目標 |
| W3-W6 | 四週打卡 |
| W7 | 期末量測、反省回饋、產出歷程檔 |

`t_start` / `t_end` 預設帶 W3 的週一到 W6 的週日，可調。

# 第一批補做・教師端明細檢視

## 問題

目前教師端只看得到「是否已完成登記」，**看不到學生填了什麼內容**。資料庫裡有、RLS 也允許教師讀自己班，是前端沒把明細接出來。

原型 `教師端進度看板_原型.html` 裡已經有這個設計（點任一格跳出該生完整資料），實作時漏掉了。

## 要補的內容

點學生格子 → 跳出明細，包含：

| 區塊 | 內容 |
|---|---|
| 身體數值 | 20 個欄位全部，超出門檻的**整列淡紅底、數字紅字**，右側標註「偏高／偏低／建議重測」 |
| 自動計算 | BMI、體脂重量、腰臀比 |
| 百分位 | 該生在全年級的位置（見第二批 G 節） |
| 自我檢測 | 生活型態、壓力、心情、飲食金字塔類型、85210 達成項目 |
| 歷次紀錄 | 期初／期中／期末切換，有多筆時顯示趨勢 |
| 目標與打卡 | 設了什麼目標、四週打卡狀況（第三批完成後接上） |

## 另外要補

- **匯出 CSV**：整班所有欄位，給蕾蕾自己留底和做課程分析
- **班級分布圖**：各項目的分布，用於課堂上談「我們這個年級的整體狀況」（呈現時去識別化）

## 權限注意

教師是**唯讀**。明細頁不提供任何編輯按鈕，學生要改資料一律自己重新登記（upsert 會更新同一筆）。

# 不可改動的設計原則（沿用並延伸）

1. 紅色警示只在教師端，學生端維持中性燈號
2. 心理檢測高風險 → 固定關懷文案，絕不接 AI，不給生活習慣建議
3. 任何頁面都不顯示目標體重、減重公斤數、熱量赤字
4. 不做學生間排名、不做班級競賽排行榜
5. 打卡中斷不使用責備性文案
6. SMART 目標一律行為型
7. 分析結果現算不落盤，維持單一真相來源
8. 座位登記與點名維持 join_code 免登入流程，不動
